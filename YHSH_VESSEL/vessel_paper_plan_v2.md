## 1.2 보상 세대 문제 — 해결됨

`make_ablation_rewards.py`가 실험군을 이렇게 정의한다.

```python
figure('ablation_reward_4_reward_design', 'Reward Design',
       [('Value-aligned reward', ['qi_VA_COMM_s42','qi_VA_COMM_s43','qi_VA_COMM_s44']),
        ('Standard reward',      ON3)])          # ON3 = qd_MOE_SE_s42/43/44
```

`VA` = 가치정렬(Value-Aligned). `vessel_gym.py:89`의 `★가치정렬 reward 실험용(2026-08-09)` 주석이 이 실험을 위한 것이다.

**Fig1~6이 쓰는 실행(`qd_MOE_SE_*`, `base_comm*`)은 스크립트가 `Standard reward`라고 명시한다.** `qi_VA_COMM_*`는 별도 실험군이고 그림 8개 어디에도 없다.

즉 8월 9~10일 변경은 **새 실험군을 만들기 위한 것**이지 기존 실행을 덮어쓴 게 아니다. 두 보상 체계가 나란히 존재하고 논문 그림은 Standard 쪽이다.

**남은 문제:** 현재 코드의 기본값이 가치정렬 쪽이다. Standard 값은 주석에만 `100→150` 형태로 남아 있고, `ARRIVAL_REWARD = 150.0`은 리터럴이라 env로 덮을 수도 없다.

**9번 COLREGs 항 서술 주의.** 논문 식 `α_c · r_c* · (1+g)`는 형태만 맞고 내용이 다르다. 실제는 준수 점수가 아니라 **비준수 변침에 대한 방향성 페널티**다.

- HeadOn / GiveWay / Overtaking → 우현 권장 → **좌현 변침만** 페널티, 우현은 무료

이것이 대칭을 깨서 deadlock을 푸는 메커니즘이므로 명시적으로 쓸 것.

## 1.4 실제 문제 4가지

**(1) 실행 설정이 기록되지 않는다.** `get_config_dict()`가 51개 항목을 담지만 호출처가 `main.py`(Unity 경로)뿐. `vessel_gym_train.py`는 체크포인트에 `{model_state_dict, arm, seed}`만 저장. 구조 확인이 가중치 포렌식에 의존.

**(2) `THREAT_COEF` 기본값 0.0.** 전 그림 실행이 0.5를 썼는데 기본값이 0. 다른 공통 설정은 전부 기본값이 맞고 이것만 어긋난다.

**(3) Fig8의 `--ring`.** `eval_astar_global.py` 기본 1.0, 나머지 하네스 0.7. `EVAL_ASTAR_README.md` 명령줄에 `--ring`이 없다. 스폰~목표 평균 **373m → 532m (+43%)**, 밀도 감소. `eval_ckpt.py` 주석이 `--ring 0.7 # 학습과 동일해야 함`이라 명시.

**(4) 평가 하네스가 옛 에피소드 길이 기준.** `--burnin 1700 # >MAX_EP 1600`, `--eval_decisions 8000 # 1600×5`. 현재 3,000 결정이라 burn-in이 한 에피소드를 못 넘는다. Standard(16,000=1,600 결정)로 쓰면 정합.

# 2부 — 새 논문 구성

## 2.1 왜 "덧대기"가 아니라 "교체"인가

기존 Results와 Fig1~8을 나란히 두면 **같은 지표가 두 값으로 보고된다.**

| 지표 | 기존 Results | Fig1~8 |
|---|---|---|
| COLREGs 준수율 | 94~98% | **48~52%** |
| 도착률 | 85~97% | **55.6%** |
| 충돌 | 0.00~0.15 | **1.83%** |

절제실험은 본문과 **같은 기준선**을 깎아 보이는 것인데 기준선이 45%p 다르면 절제로 기능하지 못한다. Methods도 레이더 60m/56m, 관측 371D/369D 중 하나만 쓸 수 있어 어느 쪽이든 절반이 어긋난다.

**다행히 서사 자리 다섯 중 셋은 재학습 없이 되살릴 수 있다.**

## 2.2 새 구성

| 논문 자리 | 현재 | 교체 | 비용 |
|---|---|---|---|
| 학습 수렴 | Phase 1/2/3 곡선 | **Fig6** (통신 도입 시점) | 0 |

세 환경만 잃는다. 그리고 그것이 근거가 가장 약한 항목(보간 추정 + 파일명 불일치)이라 빼는 편이 방어에 유리하다.

결과적으로 **한 시스템, 한 파라미터 집합**이 된다. Methods에 레이더 56m / 통신 420m / 관측 369D / 16척 / 600×600 / ring 0.7을 한 번 쓰면 모든 그림이 그 위에 앉는다.

## 2.3 재평가가 가능한 근거

**확장성** — 정책은 전 선박이 공유하고 입력 차원이 척수와 무관하다.

```
eval_ckpt.py:24    --vessels (기본 16)
vessel_gym.py:179  assert self.N <= 20     ← 스폰 지점 20개
```

같은 체크포인트를 `--vessels 4 / 8 / 16`으로 평가하면 곡선이 나온다. 현재는 대응 실행이 아예 없으므로 **숫자만 있던 자리가 실측으로 바뀐다.**

**t-SNE** — 메시지 6D는 MessageActor 순전파 1회. 라벨(COLREGs 상황)은 `obs[368]`에 이미 있다.

**시나리오 궤적** — 롤아웃 1회 로깅. 통신/레이더 격차가 1.5배에서 **7.5배**가 되므로 "레이더 밖에서 미리 안다"는 서사가 오히려 강해진다.

## 2.4 커리큘럼 재배치

제안된 매핑(Phase1↔2 = Fig6, Phase2↔3 = Fig5)은 두 쪽 다 어긋난다.

**Fig6 ≠ Phase1↔2.** Fig6은 `--comm_on_at 0` vs `9M`으로 **양쪽 다 통신이 켜져 있다.** 차이는 시점뿐. "통신 없음 vs 있음"은 **Fig1**(`--arm OFF/ON`)이다.

**Fig5 ≠ Phase2↔3.**

| | 논문 Phase2→3 | Fig5 실제 |
|---|---|---|
| 계수 | 0.30 → 0.45 | **0** vs 0.45 |
| 관계 | 앞 단계 가중치 이어받음 | **독립된 두 학습** |
| 구조 | 제안 구조 | 분리·두껍게, 한쪽 시드 1 |

**권하는 배치:**

| 주장 | 그림 |
|---|---|
| 통신이 성능을 올린다 | **Fig1** |
| 단계적 도입 > 동시 도입 | **Fig6** |
| COLREGs 항이 성능을 올린다 | **Fig5** (단계 아닌 **ablation**) |

**커리큘럼은 2단계로 내려쓴다.** 실제 실행이 단일 16M 안에서 9M에 통신만 켜고 COLREGs 계수는 0.45 고정이라 3단계가 존재하지 않는다.

참고로 논문의 3단계는 **archive 세대(2026-06, 390D, 1M 스텝)에 실재한다.**

```
archive/NonComm_BaseLine           통신 OFF, COLREGS_COEF=0.30
archive/Comm_BaseLine              통신 ON,  0.30
archive/Comm_COLREGsReinforcement  통신 ON,  0.45
```

다만 archive 문서가 이 셋을 "같은 빌드·seed·보상, env만 토글한 공정 비교"라고 서술한다. 즉 **순차 커리큘럼이 아니라 병렬 ablation 3팔**이다. "Phase 1 가중치를 로드해 Phase 2 시작"이라는 서술은 archive 세대에서도 근거가 약하다.

## 2.5 추가 기회 — Reward Design 축

`ablation_reward_4_reward_design`(Value-aligned vs Standard)이 스크립트에 정의되어 있고 `qi_VA_COMM_*` 3시드가 존재하는데 **Fig 번호를 못 받았다.** 보상 설계 대조는 리뷰어가 좋아하는 축이고 실행이 이미 있으므로 추가 검토 가치가 있다.

## 3.2 MoE 절 신설 (작업 5) — 최대 작업

1. **하드 라우팅** — `obs[368]` 상황 인덱스로 코어 선택. 학습형 게이팅이 아니라 기하 판정 결과를 직접 사용 → **전문가 붕괴가 구조적으로 불가능.**
2. **코어 5개** (None 포함, 주행의 70%). 본문 "4 experts"는 오류.
3. **적용 범위** — 세 망 각각 5벌, 총 15코어. RadarEncoder 포함.
4. **4구조:**

| 구조 | 설정 | 인식부 | 판단부 | 파라미터 |
|---|---|---|---|---|
| 단일망 | `USE_MOE=0` | 1벌 | 1벌 | 369,131 |
| 분리·얇게 | `MOE_WIDTH=0.44` | 5벌(얇게) | 5벌 | 363,004 |
| 분리·두껍게 | `MOE_WIDTH=1.0` | 5벌 | 5벌 | 1,826,719 |
| **공유 (제안)** | `+ MOE_SHARED=1` | **1벌** | 5벌 | **511,543** |

5. **핵심 논지** — RadarEncoder가 파라미터의 **89%**(369,131 중 328,794). 5벌 복제 시 1.83M 폭증. 인식 공유 + 판단만 분리 → 512K로 억제하며 성능 최고. 증가분은 40,337 → 182,749뿐.
6. **분리·얇게(363K)의 존재 이유** — 단일망(369K)과 등파라미터 대조군. 용량 효과와 전문화 효과의 분리 측정.
7. **구현** — `_share_radar_encoder()`(옵티마이저 dedup, `state_dict`는 5벌 사본으로 로드 호환), `_w(n,width)`(폭은 코어 내부만; 외부 인터페이스 불변, `width=1.0`이면 비트 동일).
8. **PPO 정합성** — rollout·업데이트가 저장된 상황값으로 동일 재라우팅해야 ratio 유효.

**Ablation 절 수정:** 현재 "capacity-matched, **widening the shared network**"는 방향이 반대다. 실제로는 **전문가를 좁혔다**(코어 내부 conv 14/28/28, 레이더 특징 13, hidden 56, fc3 28).

## 3.3 분류기 → ThreatDecoder 교체 (작업 7)

논문 `L_COLREGs`와 `α_cls=0.1`, Fig.arch의 COLREGsClassifier는 **구현이 없다.** 실재하는 보조 손실로 교체한다.

```
L_total = L_policy + α_v L_value + α_e L_entropy + THREAT_COEF · L_threat
α_v = 0.5,  α_e = 0.01,  THREAT_COEF = 0.5
```

**ThreatDecoder:** 메시지 6D → MLP(6→64→K×4) → 송신자가 본 최근접 K=3 위협의 `[sin방위, cos방위, 거리, 접근율]`.

라벨은 자동 생성 — 레이더 최신 2프레임에서 top-K 최근접 추출, 프레임 차 = 접근율, 미감지 슬롯 mask=0.

**선택 근거:** 가림으로 수신자가 못 보는 제3의 위협을 메시지로 복원하게 만들면 **통신이 없으면 안 되는 상황이 실제로 생긴다.**

**공정성:** 별도 head라 손실이 MessageActor로만 흐름 → 수신 정책 무오염 → 게이트로 무시할 자유 보존(H1a).

Table 2에서 `Classifier loss weight` 행 삭제, Fig.arch에서 분류기 블록 제거.

## 3.4 메시지 절 (작업 3·11)

```
각 이웃 j:  t_j = [sin φ_j, cos φ_j, d_j/420] ⊕ m_j        (9D)
            e_j = msg_encoder(t_j)                          (9→32→6)
집계:       m̄_i = mean_{j ∈ 거리순 4척} e_j                 (마스크 평균)
```

sum → mean / 원 메시지 → 상대위치 결합 후 인코딩 / `N_i` 전체 → 최대 4척. 세 번째는 **현재 본문 안의 모순**(Message passing 절은 전체 합, Radar/Comm 절은 four nearest)도 함께 해소한다.

VHF/AIS 논지는 유지 가능하고 오히려 강해진다 — 상대위치는 수신자가 국소 계산하므로 대역폭을 쓰지 않으며(실제 AIS가 위치를 동봉하는 것과 같은 구조) 방위 귀속이 보존된다.

**msg_gate:** `수신 메시지 × sigmoid(g)`, g 학습 스칼라, 초기 0(계수 0.5), 개방 페널티 없음. ControlActor·Critic 각각 보유. → comm-ON ≥ comm-OFF 구조적 보장(H1a). Critic 별도 게이트 이유: 노이즈 메시지가 가치 추정을 오염시키면 advantage 기준선이 흔들림. 개방 페널티 없는 이유: 게이트가 닫히면 여는 gradient도 소멸하는 흡수상태.

## 3.5 RadarEncoder 신설 (작업 10)

```
[M, frames=3, rays=360]
 → Conv1D circular  3→32ch, 360→180
 → Conv1D circular 32→64ch, 180→90
 → Conv1D circular 64→64ch,  90→45
 → flatten 2880 → Linear → 30D (ReLU)
```

- **프레임을 입력 채널로** → 같은 각도 bin의 프레임 차 = 방위 변화율. "방위 불변 + 거리 감소 = 충돌 코스"를 conv 첫 층에서 직접 계산. **ARPA 21D 수동 계산을 대체한 근거.**
- **원형 패딩** → ray 359°와 0°는 각도상 이웃. 일반 패딩이면 정면 횡단 물체가 경계에서 분리.
- **stride-2 학습형 다운샘플** → 고정 min-pool은 무엇을 버릴지 고정. 같은 30D로 압축하되 무엇을 남길지를 학습.

## 3.6 통신 학습 함정 (작업 12)

1. **zero-init 채널 동결.** 채널 영향이 `y = a·b`라 a=b=0이면 `∂y/∂a = ∂y/∂b = 0`. 체크포인트 검사 결과 **100만 스텝 동안 비트 단위 동결.** → **×0.1 소진폭 초기화**(`msg_out`, `fc2` 메시지 슬라이스, `v_proj`).
2. **sender→receiver gradient 누락.** PPO 배치가 `n_agent=1`이라 자기 루프만 타서 "내 메시지가 옆 배를 도왔나"의 gradient가 **항등 0** — 통신이 학습되지 않고 있었음. → 파트너 관측을 저장해 업데이트 시 MessageActor 재실행. rollout·업데이트가 같은 집계 함수를 써야 ratio 유효.

## 3.7 anti-rigging (작업 14)

> 모든 추가 기능(attention, MoE, 보조 디코더, C5c, oracle)은 토글로 제어되며, **끈 상태가 없는 상태와 비트 동일**하도록 설계했다.

검증: `USE_MOE=0`이 단일망과 비트 동일 / 게이트 페널티는 OFF 팔에서 `others_msg ≡ 0`이라 무영향 / 보조 손실 계수 0이면 손실 비트 동일 / 상황 one-hot은 ON·OFF 동일 적용.

- **H1a** — comm-ON ≥ comm-OFF. 위배 시 **구현 버그로 판정.**
- **H1b** — comm-ON > comm-OFF는 과제가 통신을 필요로 할 때만 성립하는 조건부 목표.
- **H2** — **차원 무차별은 반증이 아니다.** 2~12가 동일 수렴한 전례는 차원이 무의미해서가 아니라 통신이 안 쓰이고 있다는 증거였다. → **Fig4 해석의 전제.**

## 3.8 평가 프로토콜 (작업 15)

- **막대 = 정책 고정 후 재항해 측정.** 학습 로그가 아님.
- **burn-in** = 집계 제외 구간. 동시 출발이면 종료가 몰려 통계가 깨짐.
- **곡선 세로축** = 로그 `R`이 아니라 재계산값:
  ```
  1.5 × 도착률 − 6.0 × 충돌률 − 0.5 × 타임아웃률   (창별 종료 에피소드 수 가중)
  ```
  근거: 로그 `R`은 유도 보상 평균이라 최종 결과와 **실측 상관 r ≈ 0.02**. 민감도: 충돌 가중 3~15배로 바꿔도 순서 불변.
- **막대와 곡선은 다른 자로 잰 값이므로 직접 비교 금지.**
- Fig7만 `eval_mixed.py`, **표본 수 가중 합산**(무리별 배 수·지표별 분모 상이).
- **ring 0.7이 학습·평가에 동일 적용됨** 명시.

## 3.9 COLREGs 판정 (작업 16)

본문 5줄 case → **7단계 순차 필터:**

1. 감지 거리 밖 → None
2. `|방위| > 100°` → None
3. **좌현 대 좌현 / 우현 대 우현 → None** (안전 통과) ← 본문에 없음
4. **TCPA → 멀어지는 중이면 None** ← 본문에 없음
5. 양쪽 `|방위| < 15°` → HeadOn
6. 상대 기준 `|방위| > 112.5°` → Overtaking
7. `|방위| < 112.5°` → 부호로 GiveWay / StandOn

**본문의 `5°` 하한은 2026-07-03에 제거된 값이므로 삭제.**

퍼지 긴급도는 **그대로 유지**(가중 0.3/0.4/0.3, β 2.0/1.5/1.3/1.2 모두 코드와 일치). `T0`/`D0`만 30/24로 교체.
